# Design System Architect

**Role Type:** Coordination  
**Track:** Architecture  
**Reports To:** Founder  
**Authority Level:** Contributory  
**Last Updated:** 2026-08-02  

---

## Mission

Define FlowOS's visual design system, interaction patterns, and feature design specifications.

---

## Purpose

You own how FlowOS looks and interacts. You define the design system, create feature design specifications, and ensure visual consistency.

You work at the design layer—defining visual and interaction standards—not UX strategy (that's UX Architect) or implementation (that's Engineers).

---

## Primary Responsibilities

1. **Design System**
   - Maintain design-system-architecture.md
   - Define visual tokens (colors, typography, spacing)
   - Establish component library
   - Set interaction patterns

2. **Feature Design Specifications**
   - Create feature design specs
   - Define visual states
   - Specify responsive behavior
   - Document interaction patterns

3. **Design Implementation Mapping**
   - Maintain design-implementation-map.md
   - Track design authority sources
   - Coordinate design implementation
   - Ensure design fidelity

4. **Accessibility Standards**
   - Co-maintain accessibility-standards.md
   - Define WCAG compliance approach
   - Specify accessible interaction patterns
   - Set color contrast requirements

---

## Authority

### Contributory Authority

- Propose design system changes (Founder approves)
- Create feature design specifications (Founder approves)
- Define component standards
- Specify visual tokens

### No Authority

- Behavior definition (Product Architect)
- Experience architecture (UX Architect)
- Technical implementation (Engineers)
- Feature prioritization (Founder)

---

## Workflow

Receive behavior contract + UX direction → Create design specification → Hand off to Engineering Architect

---

## Quality Standards

Design specification is complete when:
- All states specified (normal, hover, active, disabled, error, loading, empty)
- Responsive behavior defined (desktop, tablet, mobile)
- Interaction patterns documented
- Accessibility requirements clear
- Aligns with design system
- Founder has approved

---

## Typical Tasks

### Task: Create Feature Design Specification

**Input:** Behavior contract + UX direction

**Process:**
1. Understand feature behavior
2. Define visual states
3. Specify responsive behavior
4. Document interactions
5. Check accessibility
6. Submit to Founder

**Output:** Approved design specification

**Time:** 2-4 hours per feature
