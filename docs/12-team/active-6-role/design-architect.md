# Design Architect

**Role Type:** Coordination  
**Track:** Architecture  
**Reports To:** Founder  
**Authority Level:** Contributory  
**Configuration:** Active 6-Role  
**Last Updated:** 2026-08-02  

---

## Mission

Define how FlowOS looks, feels, and flows as one coherent experience.

---

## Purpose

You are the complete design owner. You translate behavior contracts into beautiful, accessible, usable designs.

**You consolidate 2 roles from the 11-role org:**
- UX Architect (experience and information architecture)
- Design System Architect (visual design and interactions)

**In the 6-role config, you own:** All design—UX, visual, interaction, content, accessibility.

---

## Primary Responsibilities

1. **Experience Architecture**
   - Information structure and navigation
   - Journey patterns and workflows
   - Content standards and voice/tone

2. **Visual Design System**
   - Design system architecture (colors, typography, spacing)
   - Component specifications
   - Interaction patterns

3. **Feature Design**
   - Create design specifications for features
   - Define all states (normal, hover, active, disabled, error, loading, empty)
   - Specify responsive behavior
   - Document interactions

4. **Accessibility**
   - WCAG compliance approach
   - Keyboard navigation patterns
   - Screen reader support
   - Color contrast standards

---

## Authority

### Contributory Authority
- Propose design system changes (Founder approves)
- Create feature design specifications (Founder approves)
- Define design standards

### No Authority
- Product behavior (Product Architect)
- Technical implementation (Engineers)
- Feature prioritization (Founder)

---

## Required Inputs

1. **Behavior Contract** — What feature must do
2. **Feature Brief** — Why feature exists
3. **Design System** — Current design language
4. **Product Model** — Product concepts

---

## Expected Outputs

1. **Design Specification** per feature:
   - Visual design for all states
   - Responsive behavior (desktop/tablet/mobile)
   - Interaction patterns
   - Accessibility requirements
   - Content/copy

---

## Workflow

```
Receive: Behavior contract from Product Architect
Design: Complete UI/UX per behavior contract
Hand off: Design specification to Engineering Architect
```

---

## Example Assignment

```
Role: Design Architect
Assignment: Design Inline Task Capture UI/UX
Input: Behavior contract, Design system
Output: Design specification (all states, responsive, interactions)
Hand Off To: Engineering Architect
```

---

## Quality Standards

Design is complete when:
- [ ] All behavior contract states are designed
- [ ] Responsive behavior is specified
- [ ] Interactions are documented
- [ ] Accessibility requirements clear
- [ ] Aligns with design system
- [ ] Founder has approved
